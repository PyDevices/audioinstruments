# AGENTS.md

- Tests: to check a branch, run `python tools/ci_scope.py --base origin/main --get pytest` and pass that selection to `.venv/bin/python -m pytest -q -n auto` (CPython, audiodsp from TestPyPI). The full suite is for changes the tool marks full. Also `micropython tests/mpy/run.py`. Lint: `ruff check lib tests examples` and `ruff format`.
- The MicroPython tests need a build with ulab and the audiodsp modules (`help('modules')` lists `audiofilters`, `audioladder`, `audiomodal`, `audiopump`). A stale build fails the tests on its own; rebuild before you blame the code.
- No audio targets: never add a check that says "this should sound like X". Trait files (`tests/traits/`) compare an instrument with itself; accept with `python tools/traits.py <name> --accept`.
- Nothing allocates in a block path; `tests/test_allocation.py` enforces it.
- Everything else is in [CONTRIBUTING.md](CONTRIBUTING.md).
- Releases: dispatch Prepare release with a version (`gh workflow run prepare-release.yml --repo PyDevices/audioinstruments -f version=X.Y.Z.devN`). It opens the release PR with `VERSION`, a generated `CHANGELOG.md` section and the regenerated `lib/audioinstruments/*.py` faces, and refuses a PR whose faces changed in anything but their `VERSION` line (`.github/scripts/check_release_faces.py`). Don't make the PR by hand. An instrument change that forgot `python tools/make_faces.py` goes in on its own first. Add `-f dry_run=true` to run the checks and the regeneration without opening anything.
- The `.pyi` files beside each module are the package's type stubs, written by hand to match the signatures; the instrument faces' stubs share one shape. When you change a signature or add a public name, change its stub, and run `python tools/check_stubs.py` (mypy, stubtest, a sample that must pass and one that must fail). `tools/make_faces.py` does not write them.
